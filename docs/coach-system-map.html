Coach System — Map of What Exists

The Coach is the async learning supervisor of the cybernetic entity. It reviews a completed (or blocked) skill run and emits governance artifacts: proposals, observations, learnings. It does not touch the skill directly — every output routes to the operator for ratification. Two-step agent graph, sonnet, temperature 0, max 10 tool calls/turn. def: packages/platform-artifacts/src/cyberneticAgents.ts:1171

Run reaches terminal / skill blocked → Gate shouldActivateCoach → Rate cap → Build brief + CoachReviewContext → step 1 · review (LLM) → step 2 · validate-outcome ↺ on fail → loop back to review → Proposals staged → operator ratifies

2 · WHAT input it gets

Input is two layers: a typed CoachReviewContext (the activation's posture/authority metadata) and the prompt brief (the evidence blocks concatenated into state.prompt). Both are assembled in triggerCoachReview after the gate passes (so cost is only paid on real activations).

CoachReviewContext (typed envelope)

coachReviewContext.ts:101 · schema cybernetic/coachReviewContext.ts
  • trigger — kind, requestedBy, rationale, bypassesGate
  • target — skillSlug, runId, taskId, focusAreas
  • skillMode — optimization | process | project
  • trainingPosture — training | operational (per-skill maturity-adjusted)
  • evidenceTier · interventionLevel (from intent matrix §3)
  • validityDiagnostics[] — for repair reviews
  • appliedChangeOutcomes[] — expected vs measured lift of past ratified proposals
  • authorityEscalation — agent_signal | regression → +1 authority notch on proposals
  • breadthEvidence — campaign trajectory / case distribution
  • priorFailures — recent ratification errors, apply-preview failures, observations-by-reason

Prompt brief blocks (in order) coachTrigger.ts:924–966

  • Review head — "Review workflow X run Y", eval summary, trigger reason
  • Facts facts win on disagreement — deterministic compiled signals (+ optional LLM enrichment, deadline-raced)
  • Eval-suite snapshot — the criteria that actually graded the run (+ always-passes quality report)
  • Durable learnings — auto_recorded + ratified only
  • Applied-change outcomes — did the Coach's own past fixes work?
  • Breadth — campaign trajectory / case distribution (read run against the arc)
  • Candidate ledger — pending fast-learnings to promote/reject (campaigns)
  • Digest + digest-citation values (verbatim refs for proposals)
  • Reflections — Runner self-reports
  • Coach-feedback history + user feedback for the skill

Validity-repair variant: head replaced by buildValidityRepairPromptParts — diagnostics + live config via workflow.manage.get only; no digest/facts/enrichment (there is no graded run). coachTriggerValidity.ts

Evidence tier controls depth: default = digest+facts (reflections-first, trace skipped) · escalated = + full trace slice + ledger excerpts · deliberate = + artifact.inspect.* tools unlocked. Non-deliberate inspect calls return EVIDENCE_TIER_INSUFFICIENT.

4 · WHAT it produces

Step 1 (review) calls action tools, then complete with a structured outcome. Step 2 (validate-outcome = learner.review.finalize) validates shape + cross-checks every cited ID; on failure it writes outcome_feedback and loops back to review. cyberneticAgents.ts:1224 (graph) · :1293 (validator)

silent

clean run / eval pass / no regression.
all id arrays empty + rationale.

observation_only

anomaly or unattributable failure, no category.
learner.observation.record ×1 → observationId.

learning_only

durable cross-run claim, no skill change yet.
learner.learning.record ×N → learningIds.

with_proposals

≥1 nameable issue category.
learner.propose.workflow_change ×N → proposalIds.

Outcome also carries typed facets — always a correctness facet (per-run read, even when silent); a trajectory facet only when the brief had a campaign-trajectory block. Learnings ride additively on any outcome.

Action tools (the actual outputs)

Tool Produces Routing
learner.propose.workflow_change Staged skill mutation (one issue category each). Apply-preview runs ops against snapshot synchronously — PREVIEW_FAILED lets Coach revise in-session. → operator ratify/reject
learner.propose.artifact_update Refresh of a bundle-shipped UI card (carries a draftId from ui.artifact.generate). → operator ratify (always)
flag_pattern → platform_issue Read-only diagnostic report on a platform-owned workflow. not ratifiable — info only
learner.observation.record One-off anomaly that didn't lead to a proposal (closed-set reason). logged
learner.learning.record Durable claim. campaign→auto_recorded · skill/space→staged for ratification. ledger

Read tools (escalation only, rare, monitored): memory.store.query/get, workflow.manage.get, workflow.ledger.get, and tier-gated artifact.inspect.list/read.

5 · The framework it reasons with (the prompt)

PROMPT_COACH cyberneticAgents.ts:361–586 — "be a quality controller, not a talker." The core scaffolding it must map a run onto:

Issue-category framework (closed set — one per proposal)

Category Means
procedure wrong decomposition / ordering / missing step
context_spec wrong inputs / memory scope / Runner guidance
tool_capability wrong tool grants or needs a binding
reasoning right context+tools, Runner reasoned poorly
eval_suite eval missed/mis-scored — graded noise as signal
platform skill can't fix it → platform_issue
environment external dependency failure

Proposal warrant contract (required on every propose)

  • diagnosis.issueCategory — exactly one
  • evidence.digestRef / digestSha256 — pass-through verbatim
  • evidence.digestCitations[] — ≥1 (runId/taskId/sessionId/stepExecutionId)
  • warrant: claim (the change, not the symptom) · evidenceSummary · warrant (why evidence⇒claim) · expectedEffect · risk? · rollback?
  • artifactRefs — required if inspect.read shaped the proposal

Guardrails: facts > eval > ledger > parent summaries · don't re-propose recently-rejected ideas without new evidence · contamination rule (platform-path failures → metrics context only) · small specific proposals over rewrites · never amend governance directives · narrative ≠ a legal exit.
